## 一、加密

**目的：机密性 —— 内容不被未授权者读取**

```
原始文件 →【用接收方公钥做运算】→ 密文文件（不泄露原文）
```

**要点：**

1. 密文不泄露原文内容，只有配对的**接收方私钥**能还原；
2. RSA 一次只能处理很短的数据（2048 位密钥约 245 字节），真实加密文件采用**混合加密**：AES 加密文件本体 + 公钥加密那把 AES 密钥。

---

## 二、解密

**目的：把密文还原为明文 —— 只有接收方能做**

```
密文文件 →【用接收方私钥做运算】→ 原始文件（明文还原）
```

**要点：**

1. 解密是加密的逆运算，**必须用配对的私钥**；公钥解不开——每把钥匙只有一个"另一半"（互为模逆）；
2. 对应混合加密：私钥先解密 AES 密钥，再用该密钥解出文件本体。

---

## 三、签名

**目的：身份认证 + 完整性 —— 证明"是本人所签，且内容未被篡改"**

```
原始文件 →【先取哈希 SHA-256，得固定长度指纹 h】→【用发送方私钥对 h 做运算】→ 签名 s（固定长度，如 256 字节）
```

**要点：**

1. 原始文件**不变**，签名只是旁边多出的一段附加信息，不隐藏文件内容；
2. 签名运算的对象是**文件的哈希值**，不是文件本体（私钥模幂运算慢，且 RSA 装不下大文件）。

---

## 四、验签

**机制：用公钥"打开"签名 → 还原哈希 → 与文件哈希对比（不是"再生成一个签名对比"）**

**左路 · 还原签名里的哈希**

```
[收到的签名 s] →【用发送方公钥对 s 做运算】→ 还原出签名时藏进去的哈希 h₂
```

**右路 · 对收到的文件重新算哈希**

```
[收到的原始文件] →【用同样的哈希函数 SHA-256】→ 得到当前文件的哈希 h₁
```

**对比判定：**

- `h₁ = h₂` → 通过：确属本人所签，且文件未被篡改；
- `h₁ ≠ h₂` → 失败：非本人所签，或文件被篡改。

**关键区别：**"签名"这个动作只有私钥能做；公钥对签名做的运算本质是**还原**，不是"再签一次"，因此验签是"还原哈希 + 对比"，而非"生成另一个签名来对比"。
